        How to use this app

        Getting started

        The app opens in Leave Accounting and shows three setup steps. You can do them in any order: connect (or import) your leave database, set up leave types and entitlements, and load an attendance CSV. Everything runs in your browser — nothing is uploaded anywhere.

        Two modes

        Use the toggle in the header to switch between them. Both work off the same loaded CSV.

        • Attendance Report — the hierarchical Month → Employee → Day view with hours worked, movements (breaks), and day tags.
        • Leave Accounting — detects leave days, lets you classify them by type, and tracks per-employee balances in a saved database.

        Attendance Report

        • Click any row to expand it. Expand All / Collapse All act on everything.
        • Date filter (From / To) limits the report to a range. Handy when an export includes stray days — e.g. an "April" download that also contains 1 May. Set the range and click Apply; Reset restores the full file.
        • Day tags: Weekly Holiday / Alternate Saturday / public holidays (yellow), Not Moved In (red — a working day with no punches), Half Day Leave (blue — worked hours below the half-day threshold, default 5h, set in Leave Types & Rules).
        • A red arrow flags a day with an odd number of punches (a missing in/out), which bubbles up to the employee.
        • Total Hours = first punch to last punch. Worked Hours = total minus the time out on breaks.

        Leave Accounting

        • Process Range → DB scans the current date range and adds detected leave days (full-day absences = 1.0, half-days = 0.5) to the database. It's safe to run repeatedly — the same day is never counted twice, and any leave type you've set by hand is kept.
        • Tagging: expand an employee and pick a Leave Type for each day (Earned, Sick, Without Pay, …). Add an optional note. Days left untagged show an amber highlight and an "untagged" chip.
        • Balances per employee show as chips like EL: 9/12 (remaining / entitlement). They update as you tag.
        • Leave Types button — add or edit types and their default annual quotas.
        • Entitlements button — override the quota for a specific employee; leave a cell blank to use the type's default.

        Saving the leave database

        The leave data lives in a JSON database. How it's saved depends on where you open the app:

        • Auto-save (recommended): when the app runs from a local server or a hosted site in Chrome/Edge, click Connect folder and pick the folder that holds your leave_db.json and your attendance CSV exports. The database auto-saves to that folder about a second after each change, and your CSVs in the same folder show up in the Load attendance CSV list. Put the folder inside Google Drive (or similar) and everything is backed up to the cloud and shared across machines — no accounts or keys needed. The dot in the toolbar shows Saving / Saved / Unsaved.
        • Import / Export: always available. Export downloads leave_db.json; Import loads one back. Use this if auto-save isn't available in your setup — the file format is identical either way.

        To enable auto-save locally: put the HTML file in a folder, run python3 -m http.server 8000 in that folder, and open http://localhost:8000/ (then the file name). Opening the file directly by double-clicking won't allow auto-save — use Import/Export there.

        Fetching attendance from the cloud

        Instead of exporting a CSV by hand, you can pull records straight from CrossChex Cloud with Fetch from cloud. Because the CrossChex API blocks direct browser calls (CORS), this needs a small local proxy:

        • Install once and run: npx local-cors-proxy --proxyUrl https://api.us.crosschexcloud.com — it listens on http://localhost:8010/proxy.
        • In Fetch from cloud, set the proxy URL to http://localhost:8010/proxy/ (trailing slash matters), enter your API key and secret, pick a date range, and fetch. Records are paged automatically and converted from UTC to IST.
        • The fetched data loads just like a CSV, and (by default) is also written as a CSV into your workspace folder so cloud and manual data look identical.
        • Test token checks the connection without fetching anything.

        Credentials & security: the proxy only fixes CORS — your API key/secret still pass through it from the browser. If you tick “Remember”, they're stored locally in this browser (IndexedDB), never in leave_db.json and never in the workspace folder. On a public (e.g. GitHub Pages) URL they're readable by anyone with access to the page, so only use the cloud fetch on a trusted machine.

        Loading multiple attendance sources

        You can load several CSVs at once and combine them with cloud fetches — useful for tracking a full year across many monthly exports. Each load adds to the working set rather than replacing it.

        • Pick multiple files in the OS dialog, or tick several rows in the in-folder picker and click Load selected.
        • The Attendance bar shows each loaded source as a chip with its record count and date range. Click × on a chip to remove just that source; clear all drops them all.
        • If two sources overlap (e.g. an April export that also contains 1 May, plus a separate May export), the overlapping punches are detected and dropped from the later source, so nothing is double-counted. The chip shows how many records were duplicates.
        • Single-CSV math is preserved: the app never deduplicates within one source — only across sources.

        Leave database structure

        The leave_db.json file has two top-level blocks:

        • config — leave types, the half-day threshold, per-employee identity, and entitlements. This is the slow-changing setup.
        • records — the leave ledger, keyed by employee number then by date.

        To start a fresh ledger while keeping types and entitlements: click Clear leave records in the persistence bar, or open leave_db.json in any editor and set "records": {}. Either way, your config stays untouched.

        Good to know

        • The app shows exactly what's in the CSV. If an export includes an unexpected day, that day really is in the file — use the date filter to scope it out.
        • Leave days are keyed by employee + date, so re-processing a range is always safe.
        • Single editor at a time is assumed. If the same database file is edited from two places via cloud sync, the last save wins.
        • Older leave_db.json files (pre-config/records split) are migrated automatically on import or when reconnecting the workspace folder.
